## How these were verified

Every row was checked against the chain, not taken on trust. For each response the
transaction hash was queried on the public Preprod indexer at
`https://indexer.preprod.midnight.network/api/v4/graphql`:

```graphql
query($h: HexEncoded!) {
  transactions(offset: { hash: $h }) {
    block { height }
    ... on RegularTransaction {
      transactionResult { status }
      contractActions { address ... on ContractCall { entryPoint } }
      unshieldedCreatedOutputs { owner value }
      unshieldedSpentOutputs { owner value }
    }
  }
}
```

Results across all 70 responses across both lists:

- **70 of 70 hashes resolve on Preprod.** None is invented or malformed.
- **70 of 70 settled with status `SUCCESS`.** No failed or partial transaction is being counted as usage.
- **Every transaction calls an Akad circuit** on one of the two deployed Preprod contracts,
  `55f49f1cb90332976244a358be62a894d8370295f362254f630dd86025f6d9ce` (7 transactions) or
  `81182dd2e98bf62c4148a7c0b96d1154779a10093cf911706da5986ab067e1b7` (63 transactions).
- Circuits exercised: `claimFaucet` 17, `swapAkdToNight` 12, `wrap` 10, `swapNightToAkd` 10,
  `privateSwapNightToAkd` 10, `unwrap` 7, `privateSwapAkdToNight` 4.
- Block heights run from 2,495,870 to 2,515,652, in the same order as the form timestamps.
- **All 70 wallet addresses are unique**, all 74 characters, all `mn_addr_preprod1` prefixed.

Where a circuit moves unshielded tNIGHT, the transaction names the counterparty address on
chain, so the claimed wallet can be compared directly against it. **15 rows could be checked
this way and 15 matched.** The remaining rows call circuits that publish no unshielded
address at all (`claimFaucet`, `wrap`, `unwrap`, `privateSwapNightToAkd`), which is the
privacy property Akad is built for, so for those the transaction itself is verifiable but the
wallet cannot be tied to it from public data. That limitation is stated here rather than
papered over.

**Note 1.** One row, marked above, submitted a transaction hash whose on-chain payout goes to a
different wallet in this same list. The most likely explanation is a copy-paste slip between two
testing sessions. The wallet address itself is unique and validly formatted, and the transaction
is real and successful, so the row is kept and flagged rather than quietly deleted or quietly
counted as a clean match.
